# ADR-0001: Initial v0.1 research boundary

- Status: Proposed
- Date: 2026-08-02
- Decision owners: project maintainers

## Context

QBitPlan investigates whether query-conditioned, interaction-aware bit
planning can preserve model quality under a resource budget. The research
brief identifies upstream precision interactions and causally available
execution signals as central research concerns. It is background input, not an
accepted specification or verified bibliography.

The research space includes many possible bit widths, granularities,
controllers, quantization targets, serving layouts, datasets, and hardware
backends. Attempting all of them in v0.1 would prevent clear falsification.

## Accepted premises and invariants

The following are accepted for the current documentation contract:

- Layer-group precision decisions may interact through upstream execution
  context. The independent planner is a baseline, not a scientific
  independence assumption.
- A quantized result is compared with a declared high-precision reference;
  the reference format remains OPEN.
- Ground truth and reference execution are distinct. Primary quality metrics
  and diagnostic metrics must not be conflated.
- Causal signals may control only decisions that occur after those signals are
  available, and their computation counts toward cost.
- Simulated, lookup-table estimated, and directly measured cost are reported
  as separate evidence classes.

## Proposed v0.1 boundary

Constrain the first research contract to:

- weight-only quantization;
- bit widths {4, 8};
- eight contiguous layer groups;
- one bit choice per group;
- single-query execution;
- independent MCKP as the mandatory additive baseline;
- one interaction-aware planning method;
- one query-only variant;
- one causally valid probe or feedback variant;
- an offline oracle;
- explicit separation of simulated and measured cost;
- no requirement for a custom serving engine or custom CUDA kernels.

This boundary is PROPOSED; it is not an implementation authorization. The
exact interaction-aware algorithm and controller architecture are OPEN.

## Deferred scope

Defer beyond v0.1:

- activation quantization;
- KV-cache quantization;
- 2-, 3-, and 6-bit execution;
- per-head and per-channel routing;
- dynamic batching;
- full token-level adaptation;
- linear-attention controllers;
- custom CUDA kernels;
- a large custom serving engine.

These are scope exclusions for the first contract, not claims that the
directions are unpromising.

## Rationale

The constrained formulation permits all 256 binary profiles to be enumerated
for a small eight-group pilot. This supports a clear signal, interaction, and
oracle-headroom test before investment in a more complex controller. It also
keeps the distinction between an executable bit profile and a measured
hardware benefit explicit.

## Consequences

- The initial result may not establish production serving viability.
- Simulated or fake-quantized results must not support memory or latency
  claims.
- The first implementation, if later authorized, should optimize experimental
  clarity rather than serving throughput.
- Expanding the boundary requires a superseding ADR.
- A sophisticated controller should not be developed if the oracle offers
  little benefit over a static profile, unless a later ADR changes that
  premise.

## OPEN decisions

The following choices are intentionally unresolved and must not be inferred
from this ADR:

- model identifier and exact revision;
- high-precision reference format, such as whether it is BF16;
- quantization implementation or library;
- Python environment, dependencies, and orchestration stack;
- datasets, dataset revisions, and split/query-ID manifests;
- experiment-specific primary and diagnostic metrics;
- accepted degradation threshold;
- target hardware and execution backend;
- measured cost dimensions and cost coefficients;
- interaction-aware algorithm and controller architecture;
- number of profile medoids or library size;
- serving layout and any prefetch/cache policy.

Metrics remain OPEN at the protocol level, but every experiment must
predeclare a task-appropriate primary metric and supporting diagnostics. For
answer tasks, correctness remains the final quality metric; for
language-modeling tasks without task labels, perplexity may be primary.

## Acceptance condition

Change this ADR from PROPOSED to ACCEPTED only after the maintainers confirm
that the v0.1 boundary and its deferrals are intentional. Acceptance of this
ADR does not accept any item listed under OPEN.
